# Daily Note — 2026-06-09

## Focus

Get the app running locally and "finish the platform". Two distinct problems turned out to be in play: (1) the course system was missing from `main`, and (2) several admin nav destinations were never built.

## Work Log

- **Local setup** — Installed deps, created `.env` (Neon `DATABASE_URL`, generated `AUTH_SECRET`, SMTP), `prisma generate`. App started on http://localhost:3000.
- **Discovery** — `/admin/courses`, `/admin/sessions`, `/admin/content` returned 404. The Prisma schema on `main` only had auth/tenant/group models, yet the Neon DB already held course data (3 courses, 16 lessons, etc.). The docs (manifest/knowledge) described a far more complete system than `main` contained.
- **Root cause** — The full course + learner system lived on `feature/course-management` (PR #6, +20.7k lines, security-hardened) but was reset out of `main` on 2026-06-05 (backup branch `backup/pre-reset-2026-06-05`). Docs were written 2026-02-26 to describe that branch; main was behind.
- **Recovery** — Merged `feature/course-management` into `main` locally. Fixed an invalid schema the branch was committed with (`Tenant.courses Course[]` had no opposite relation; course models use scalar `tenantId` only — removed the orphan line). `prisma db push` confirmed the Neon DB was already in sync with the recovered schema. `next build` green (21 routes). Courses + learner experience restored.
- **New sections** — Added schema (additive, pushed, no data loss): `TrainingSession`, `SessionEnrollment`, `MediaAsset`, `SsoConnection`, `ScimToken`, `Webhook`, `WebhookDelivery`, `LtiPlatform`, `AuditLog`. Built via a 4-way parallel agent workflow + per-section adversarial hardening pass:
  - **Sesjoner** (`/admin/sessions` + `/learn/sessions`) — CRUD, capacity-aware waitlist, attendance, learner self-enroll; `session-events`-gated; audit-logged.
  - **Innhold** (`/admin/content`) — media library (extended `/api/upload` type=media → `MediaAsset`) + cross-course content browser.
  - **Rapporter** (`/admin/reports`) — KPIs, per-course/group/department completion, 30-day activity, CSV export (`csv-export`-gated, formula-injection-safe).
  - **Integrasjoner** (`/admin/integrations`) — SSO/SCIM/Webhooks/LTI config + audit viewer; HMAC-signed webhooks; hashed SCIM tokens; real authenticated `/api/scim/v2/Users`.
- **Verification** — `tsc --noEmit` clean; `next build` green (27 routes); routes resolve (307 unauth); SCIM endpoint returns spec-compliant 401 on no/bad token. Committed locally (not pushed).

## Decisions Made

- **Recover, don't rebuild** — The course work existed and was reviewed; merging PR #6 beat re-implementing 20k lines. See ADR-007.
- **Integrations are config-only for now** — SAML/LTI runtime handshakes are out of scope for a single session and security-critical; built management surfaces + storage + working SCIM read/create + signed webhooks, and documented the runtime gaps honestly to avoid repeating the doc/code drift. See ADR-008.
- **Schema centrally, UI in parallel** — Did all schema changes myself before fanning out, so parallel agents couldn't conflict on `schema.prisma`.

## Discoveries

- The DB is the source of truth and was ahead of `main`'s code — `db push` reported "already in sync" after recovery, confirming the merge was correct.
- The adversarial hardening pass caught real issues: learner/admin feature-gating bypasses (sessions), CSV formula injection (reports), and a SCIM plan-gating bypass on the public API.
